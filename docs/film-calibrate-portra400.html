Film-calibrate CLI spec — example: Kodak Portra 400

Specification for a future --release Rust CLI. It is not implemented in the film engine, pipeline, or stock/*.rs. Do not paste fitted numbers into production stocks or drift pins from this document.

Stock chosen: Kodak PROFESSIONAL PORTRA 400 (C-41 color negative).

Why this one: In ../film-data it is the sheet with the most usable data — vector plots (not a scan) of H&D, log spectral sensitivity, spectral dye density, and MTF, plus construction text (ISO, T-Grain, acetate thickness, reciprocity, process). Ektar 100 (e4046_*) is the same Kodak layout and can reuse every step. CineStill / VISION3 50D is a worse first example: that motion sheet is not in film-data.

The CLI never invents a second renderer. It fits numbers into the existing FilmStock / scatter fields. Portra vs CineStill halo differences stay an emergent stack + R property, not a look slider.

1. Parse the PDF (extract, do not OCR first)

Kodak E-series sheets in this archive are vector. The curves page is one content stream that contains the titles:

  • Characteristic Curves — Status M, daylight, log exposure in lux-seconds
  • Spectral-Sensitivity Curves — log S vs nm, density criterion 0.2 > D-min
  • Spectral-Dye-Density Curves — D-min and midscale-neutral vs nm
  • Modulation Transfer Function — response % vs cycles/mm (ticks 1…200)

CLI steps:

  1. Inflate Flate content streams.
  2. Locate each plot by its title string and the axis tick strings (LOG EXPOSURE, WAVELENGTH (nm), SPATIAL FREQUENCY (cycles/mm), …).
  3. Collect path operators (m / l / c / v) that fall inside that plot’s clip rectangle. E-4050 uses cubic Béziers for the dye-density and sensitivity traces (hundreds of c/l ops on the curves page).
  4. Flatten each Bézier to a polyline in PDF user space.
  5. Map user-space (x, y) to data coordinates using the printed tick positions, not guessed plot limits:
    • H&D: x = log10(H / lux·s), y = Status M density
    • Sensitivity: x = λ (nm), y = log10 S
    • Dye density: x = λ (nm), y = diffuse spectral density
    • MTF: x = log10(ν / (cycles/mm)), y = response (0–1, not percent)
  6. Write one CSV per plot, with the citation in a header comment.

If Bézier extraction fails for a plot, rasterize that page only and require a human-digitized CSV (WebPlotDigitizer). Do not mix a guessed axis scale with vector paths.

Channel identity on Kodak plots (Status M / forming layer, not RGB display):

3. Spectral sensitivity → spectral_sensitivity

Sheet definition: log sensitivity = log10(1/H), H in erg/cm², for the exposure that produces Status M density 0.2 above D-min, daylight, 1/50 s effective exposure, Log H Ref: -1.44.

CLI steps:

  1. Sample each extracted log-S curve onto the runtime grid 400, 420, …, 700 nm (16 points). Linear interpolate in λ; do not extrapolate outside the plotted range (zero those samples, as CineStill already does for unplotted tails).
  2. Convert log S → relative linear sensitivity S = 10^(log S − log S_max_channel) per curve so each channel peaks at 1. Keep the inter-channel peak ratio from the sheet (do not independently normalize B, G, and R to 1 if the plotted log-S peaks differ — those ratios are real).
  3. Assign the same 16-vector to fast and slow of that color.
  4. Report reconstruction RMS: interpolate the 16-grid back to the extracted polyline and print max/RMS error (same idea as pichromatic/docs/portra400-calibration.md).

This replaces the current Gaussian stand-ins (blue_sensitivity_curve peak 400 nm, green 545 nm, red 645 nm).

4. Spectral dye density → coupler epsilon and mask

The sheet plots diffuse spectral density of:

  • Minimum density (orange mask + base + fog)
  • Midscale-neutral (image dyes + D-min)

CLI steps:

  1. D_image(λ) = max(D_mid(λ) − D_min(λ), 0).
  2. Split D_image into three dye spectra by the usual Y/M/C peaks (yellow ~440 nm, magenta ~540 nm, cyan ~680 nm on this family of sheets). If the plot is already three traces, use those traces; if it is a single midscale envelope, the CLI must say it cannot uniquely unmix and stop the dye fit.
  3. Peak-normalize each dye → DyeCoupler.epsilon on the 16-λ grid.
  4. Peak-normalize D_min(λ) → mask_epsilon (replace orange_mask_epsilon()).
  5. Do not set d_max from the midscale plot. Midscale is one exposure, not D-max. d_max comes from the H&D shoulder in §5.
  6. Do not change MASK_DENSITY_FRACTION_OF_DMAX (0.4) from this plot. That constant folds mask into 0.4 × d_max; a real D-min spectrum is a different parameterization. The report should flag: sheet D-min vs model 0.4·d_max·mask_epsilon. Fitting a new mask fraction is a separate, explicit change — not part of the first CLI.

5. H&D → gamma_contrast, d_max, then capture_k

Sheet: daylight, Status M, three forming-layer curves, density vs log exposure (lux-seconds).

CLI steps:

  1. For each of Y/M/C:
    • D_min: density of the toe plateau (or the leftmost plotted point if there is no plateau).
    • Straight-line γ: slope dD / d(log10 H) on the mid-region the sheet actually draws as a line. This is Status M composite γ, not the model’s per-layer gamma_contrast until you check the mapping below.
    • D_max: shoulder if the curve flattens; otherwise “not on plot” and keep the current stock d_max with a warning.
  2. Map γ into gamma_contrast only after stating the model law: D_image = d_max · f_eff^(1/γ) in development/reduction.rs. Datasheet γ is D vs log H of the processed stack. The CLI must run the forward expected model (no grain) on uniform patches:
    • Build fluence from the sheet’s log H (lux-seconds → photons/µm² using the same radiometric path as expose, or report that this unit conversion is a remaining gap — see missing data).
    • absorb_stack → capture LUT → reduce expected density.
    • Compare Status M–like dye integrals to the extracted H&D.
  3. Solve capture_k per color (same k for fast/slow first; then optionally two k’s if the residual is clearly toe vs shoulder). Objective: mid-scale density error, not a painted curve. Toe/shoulder mismatch stays in the residual plot.
  4. Split d_max across fast/slow with the existing 50/50 split unless a cited source says otherwise. E-4050 does not.

Do not add a tone curve, lift, or second γ to hide a bad capture LUT.

6. MTF → scatter (σ_core, λ_tail, w) per B/G/R

This is the turbidity fit. It must match the kernel the renderer uses, not a Frieser K that the CPU path does not run.

Runtime mix (s = 1):

Φ' = (1 − w) · G(σ) * Φ  +  w · Exp(λ) * Φ

MTF of that mix, with σ and λ in millimetres, ν in cycles/mm:

  • Gaussian: M_G(ν) = exp(−2 π² σ² ν²)
  • 2D exponential exp(−r/λ) / (2π λ²): M_E(ν) = [1 + (2π λ ν)²]^(-3/2)
  • Mixture: M(ν) = (1 − w) M_G(ν) + w M_E(ν)

CLI steps:

  1. Extract MTF. If the sheet has one curve (typical for this Portra publication), fit one (σ, λ, w) and copy it to B, G, and R. Report that layer-resolved scatter is not in E-4050 — do not re-impose the spektrafilm red-core > blue-core ordering.
  2. If three curves exist, fit each and store as SCATTER_*_BGR.
  3. Drop or down-weight points with M > 1 (adjacency / Eberhard). Those are adjacency_beta in development, not irradiation. Fitting them into w will make the emulsion look sharper than the gelatin is.
  4. Least-squares in log ν, typically 10–80 cy/mm (where the tail actually moves). Print RMS and a plot of sheet vs model MTF.
  5. Convert σ, λ from mm to µm for the constants (× 1000).

Compare the fit to the current global placeholders (SCATTER_CORE_UM_BGR = [1.6, 2.0, 2.2], tails [9.1, 9.7, 9.3], weights [0.67, 0.65, 0.78]), which are spektrafilm defaults, not E-4050.

7. Bounce / halation — what the sheet can and cannot do

E-4050 does not plot backing reflectance or an AH absorption spectrum.

What it does give:

  • 135 support: 0.13 mm acetate. Order-of-magnitude check on psf_halation_um (current Portra: 70 µm). Spektrafilm’s still/acetate prior is ~65 µm for 120–140 µm triacetate. The CLI should print “base thickness 130 µm; current Gaussian bounce σ = 70 µm” and not set R from thickness.
  • Construction: this is a still color negative with antihalation (has_ah_layer = true). Keep the in-stack AH layer in the template. Do not delete it because CineStill has none.

AntihalationModel.reflectance (current peak 0.06 at 680 nm) stays a cited placeholder until measured. The CLI prints it as unfitted.

10. Order of work for the actual CLI (when implemented)

  1. Vector extract → CSV for the four E-4050 plots (Portra 400 2016).
  2. MTF fit only (scatter). Smallest useful engine input.
  3. Sensitivity resample onto the 16-λ grid.
  4. Dye-density → epsilon / mask shape.
  5. H&D → γ / d_max / capture_k with a residual report.
  6. Repeat the same binary on e4046_ektar_100-2016.pdf (same layout).
  7. Add VISION3 50D / H-1-5203 to film-data before claiming CineStill MTF from Kodak.

Until step 2 exists, CPU scatter stays the global spektrafilm BGR placeholders. Until R is measured, Portra’s weaker halo vs CineStill still comes from the AH layer + R = 0.06 vs no AH + R = 0.10, not from this CLI.
